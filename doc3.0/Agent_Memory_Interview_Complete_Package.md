## 📊 8 道核心题速查表

| 题号 | 问题 | 核心关键词 | 30 秒回答 |
|:---:|---|---|---|
| Q1 | Memory 怎么做及插入上下文？ | 三层架构、动态注入 | 三层架构（Short/Long/Error），每次 LLM 调用前动态拼接到 System Prompt |
| Q2 | 如何考虑上下文长度？ | 滑动窗口、按需检索 | Short-term 滑动窗口，Long-term 按需检索 top-k，总预算约 15K tokens |
| Q3 | 结构化与文本信息怎么区分？ | 分层存储、去重 | Short-term 存结构化 JSON，Long-term 存文本摘要，相似度 > 80% 去重 |
| Q4 | 记忆冲突怎么解决？ | 时间戳、重要性 | 时间戳 + 重要性综合评分，越新权重越高，高优先级优先 |
| Q5 | 记忆怎么写入上下文？ | 四段式、分段标记 | 四段式结构，Memory 通过标记注入到 System Prompt |
| Q6 | 上下文结构是四个环节吗？ | 标准四段式 | 是的，System Prompt、Historical Messages、Tool Interactions、Current Query |
| Q7 | 上下文超长怎么办？ | 不压缩、截断 | 不用 LLM 压缩，用滑动窗口截断 + 按需检索，简单高效零成本 |
| Q8 | 压缩丢失工具调用怎么办？ | 完整对、缓存 | 多层防护：保留完整对、Tool Cache、Long-term 记录、System Prompt 提示 |

## 🎯 高频追问速查表

| 追问 | 核心回答 |
|---|---|
| 用户偏好频繁变化怎么办？ | 时间衰减策略，越新权重越高，自然覆盖旧偏好 |
| Long-term Memory 会无限增长吗？ | 不会，有去重（80% 阈值）和定期清理（TTL） |
| 如何保证 Memory 一致性？ | 单 Agent 用锁，多 Agent 用分布式锁或独立 Memory |
| Memory 如何处理敏感信息？ | 输入过滤、加密存储、访问控制三层防护 |

## 💡 面试加分项

### 1. 展示系统思维

```
"Memory 系统和 Agent 的其他组件紧密配合：
- 和 Planner 配合：检索历史经验，辅助规划
- 和 Executor 配合：记录工具结果，避免重复
- 和 Reflector 配合：记录错误，持续改进
这是一个完整的闭环。"
```

### 2. 提出优化方向

```
"当前实现已经能满足需求，但还有优化空间：
【性能】用 embedding 替代关键词匹配
【功能】支持多模态 Memory（图片、代码）
【工程】分布式 Memory，支持多 Agent 共享"
```

### 3. 对比其他方案

```
"Memory 系统有多种方案：
【MemGPT】全量 LLM 压缩，成本高延迟大
【LangChain】向量检索，部署复杂
【DevPalAgent】滑动窗口 + 按需检索，简单高效
我们选择方案 3，在成本、延迟、效果之间取得最好平衡。"
```
