╚═══════════════════════════════════════════════════╝

LLM 输出
   │
   ├─► HallucinationDetector.detect()
   │      │
   │      ├─► tool_call 检测
   │      │      ├─ 工具是否存在？
   │      │      ├─ 参数是否为空？
   │      │      ├─ 是否危险操作？
   │      │      └─ 参数是否合理？
   │      │
   │    ├─► plan 检测
   │      │      ├─ 引用工具是否正确？
   │      │      ├─ 步骤是否具体？
   │      │      └─ 可行性是否过度自信？
   │      │
   │      ├─► code 检测
   │      │      ├─ 是否有 TODO 标记？
   │      │      ├─ 是否有占位符变量？
   │      │      └─ 函数/类是否存在？
   │      │
   │      └─► fact 检测
   │             ├─ 是否有不确定表述？
   │             ├─ 是否有过多数字陈述？
   │             └─ 是否引用了论文/研究？
   │
   ├─► 风险等级评估
   │      ├─ 🔴 高风险: 工具不存在、参数空、危险操作
   │      ├─ 🟡 中风险: TODO标记、占位符、过度自信
   │      └─ 🟢 低风险: 不确定表述、步骤模糊
   │
   └─► 输出检测报告
          ├─ 风险等级
          ├─ 问题列表
       ├─ 修复建议
          └─ 是否需要人工确认

╔═══════════════════════════════════════════════════════════════╗
║                      核心创新点                       ║
╚═════════════════════════════════════════╝

1. 规范优先 (Spec-First)
   └─ 需求规范 → 增量变更 → 工件关联 → 状态持久化

2. 四层验证 (4-Layer Validation)
   └─ Format → Semantic → Parser → Business

3. 防幻觉体系 (Anti-Hallucination)
   └─ 工具调用/计划/代码/事实 四维检测

4. 11阶段工作流 (11-Phase Workflow)
   └─ 从需求文档到可交付项目的完整自动化

5. 增量变更 (Delta Engine)
   └─ 增量写入而非全量覆盖，支持冲突检测和回滚

6. 工件依赖图 (ArtifactGraph)
   └─ 自动关联代码/测试/文档，影响范围分析

7. 事件总线 (EventBus)
   └─ 发布订阅架构，优先级队列，解耦通信
