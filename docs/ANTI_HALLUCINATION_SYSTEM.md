## 系统概述

DevPal Agent 的防幻觉系统采用 **"事前 - 事中 - 事后** 全链路防御体系，在 LLM 输出的每一个关键节点都植入检测机制，从根源上减少 AI 幻觉带来的风险。

### 设计哲学

1. **多层防御**：不依赖单点检测，多层冗余校验
2. **深度集成**：与 Planner / AgentEngine / Reflector 深度集成
3. **智能修复**：检测到问题后不仅警告，还能自动修复常见幻觉
4. **学习进化**：通过记忆系统记录幻觉模式，持续优化

## 检测类型与覆盖范围

### 1. tool_call - 工具调用检测

| 检测项 | 风险等级 | 触发条件 | 处理方式 |
|--------|---------|----------|---------|
| 工具不存在 | HIGH | 工具名称不在 ToolRegistry 列表中 | 阻止执行 |
| 参数空值 | HIGH | 参数值为 None / null / 空字符串 | 尝试自动修复 |
| 高风险操作 | HIGH | 含 delete/remove/drop/format 等 | 警告 + 需确认 |
| 参数过长 | MEDIUM | 参数字符数 > 1000 | 警告但继续 |

### 2. plan - 执行计划检测

| 检测项 | 风险等级 | 触发条件 | 处理方式 |
|--------|---------|----------|---------|
| 不存在工具引用 | HIGH | 步骤中 tool_needed 不存在 | 标记问题 |
| 步骤描述模糊 | LOW | 步骤描述过短 < 10 字符 | 警告 |
| 可行性评分过高 | MEDIUM | 100% 自信但步骤简单 | 降低评分修正 |

### 3. code - 代码幻觉检测

| 检测项 | 风险等级 | 触发条件 | 处理方式 |
|--------|---------|----------|---------|
| TODO/FIXME 标记 | MEDIUM | 代码中含未完成标记 | 发出警告 |

| 引用函数不存在 | MEDIUM | 生成代码调用原文件不存在的函数 | 发出警告 |

### 4. fact - 事实性陈述检测

| 检测项 | 风险等级 | 触发条件 | 处理方式 |

## 参数智能修复机制

### 修复流程

```
LLM 生成工具调用参数
        │
        ▼
    参数是否完整？ ──否──▶ 阻止执行
        │
        是
        ▼
    是否链表操作？ ──否──▶ 直接执行
        │
        是
        ▼
┌───────────────────────────┐
│  1. 强制统一 list_name = demo_list
└───────────────────────────┘
        │
        ▼
┌───────────────────────────┐
│  2. 根据步骤描述修正 operation
│     "创建"  → create
│     "删除"  → delete_at / delete_value
│     "显示"  → get_list
│     "添加"  → append
└───────────────────────────┘
        │
        ▼
┌───────────────────────────┐
│  3. 从用户查询中提取真实参数
│     正则匹配数字
│     提取文件名/路径
│     识别操作类型
└───────────────────────────┘
        │
        ▼
    重新校验参数
        │
        ▼
    执行工具调用
```

### 支持自动修复的参数类型

| 参数类型 | 修复策略 |
|---------|---------|
| 链表名称 | 强制统一为 `demo_list`，防止 LLM 编造不同名称 |
| 操作类型 | 根据步骤描述中的关键词映射到正确操作 |
| 节点数值 | 从用户查询中用正则提取真实数字 |
| 删除索引 | 根据"第 N 个"关键词转换为 0-based 索引 |
