## 二、面试重点内容分析

### 1. AI Pipeline Engine项目（核心亮点）

**项目背景**:
- 基于Spec-First理念，从需求到代码全自动化
- 解决Claude AI编码需要频繁人工介入的问题
- 目标：提效整个工程链路

**技术架构**:
```
需求输入 → 需求文档生成(含校验) → 技术文档生成(Reflection)
    ↓
子需求拆分(树状关联结构) → 源码生成 → 测试用例生成
    ↓
自动化测试(重试+模型升级机制) → 质量门禁(4道卡口) → 产物输出
```

**核心技术亮点**:
- **Prompt Caching**: 利用Claude 5分钟TTL机制，节省60% token
- **多语言插件系统**: C++/Shell/Python（已实现），Java/Go（计划中）
- **模型升级策略**: Sonnet → Opus（3次重试后升级）
- **Memory机制**: 历史经验总结，避免重复错误（如C++缺构造函数问题）
- **EventBus**: 全流程可视化，每个节点可追踪
- **质量门禁**: 4道卡口（语义/逻辑/业务理解/词性校验）

**当前状态**:
- 已在几个小项目试运行
- 主要由候选人独立开发
- 使用方式：CI集成（计划VS Code插件+可视化界面）
- 需求端仍需产品与研发先校准

**技术深度体现**:
- 对Transformer原理有研究（注意力机制优势：并行计算、长距离依赖）
- 了解Claude开始机制演变（从更长时间缩减到5分钟）
- 实践过Prompt工程（针对C++场景优化系统提示词）

### 2. 性能优化经验

**核心指标**:
- Crash率：0.6% → 0.1%（阿里）
- 卡顿率：降低8%（大疆）
- 启动耗时、CPU占用、帧率

**方法论**:
1. 摸底当前指标
2. 调研竞品（通过内部渠道获取数据）
3. 技术可行性评估
4. 与老板讨论确定目标
5. 数据驱动分析瓶颈

**竞品对比手段**:
- 内部渠道获取数据
- 实测对比（相同视频推流，对比CPU、画质、卡顿）

### 3. Qt → Electron架构迁移

**背景**:
- 2021年，淘宝直播从基于OBS的Qt版本迁移
- 驱动因素：
  - 开发效率低（2-3个C++人员）
  - Mac版本需求
  - 需要前端同学参与业务开发

**迁移策略**:
- MVP先行：优先P0/P1功能（推流、美颜、绿幕）
- 种子用户定向灰度
- 逐步迭代高级功能
- 历时约1年

**角色**:
- 架构设计
- 核心功能开发（推流/美颜/绿幕/IPC）
- 前期也写前端代码（打包/签名）
- 后期前端资源充足后专注底层
