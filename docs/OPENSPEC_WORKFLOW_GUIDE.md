# OpenSpec 9-Phase Workflow Guide

## Overview

OpenSpec 自动流程现在已完全集成到 Agent 的 Chat 模式中。当用户输入包含需求实现请求时，
系统会自动检测并触发完整的 9 阶段需求驱动开发流程。

## How It Works

```
User Input
    |
    v
[Detection: Is it a requirements implementation request?]
    |
    +-- NO --> Normal Plan-Act-Reflect loop (existing flow)
    |
    +-- YES --> OpenSpec 9-Phase Workflow
        |
        v
        Phase 1: Parse requirements document
        Phase 2: Create project structure
        Phase 3: Generate core code
        Phase 4: Code review
        Phase 5: Auto fix
        Phase 6: Generate test documentation
        Phase 7: Generate test code
        Phase 8: Run tests
        Phase 9: Update final report
```

## How to Trigger

Just enter any of these in chat mode:

```bash
# 方式1: 明确指定需求文件
> 完整实现 requirements/cpp_authentication_system.md 中的所有需求
> 实现需求文档 requirements/login_requirements.md

# 方式2: 使用关键词 + 需求文件
> 开发需求文件 requirements/my_project.md
> requirements 实现
> OpenSpec流程启动

# 方式3: 带需求文件路径
> 请实现 ./docs/req_api.md 的全部功能
```

## Configuration

You can configure OpenSpec workflow behavior in `AgentConfig`:

```python
from devpal.core.agent_engine import AgentConfig

config = AgentConfig(
    # 保留现有配置
    enable_planning=True,
    enable_reflection=True,
    
    # OpenSpec 相关配置已默认全部启用
    enable_validation_engine=True,
    enable_spec_engine=True,
    enable_artifact_graph=True,
    enable_delta_mode=True,
)
```

## Supported Requirements Document Format

Place your requirements document as a Markdown file with this format:

```markdown
---
title: Your Project Name
version: 1.0
author: Your Name
created: 2026-05-08
---

# Project Title

## REQ-001: Feature Name

**描述**: Describe the feature

**验收标准**:
- [ ] Acceptance criteria 1
- [ ] Acceptance criteria 2
- [ ] ...

**优先级**: 1
**标签**: security, user management

---

## REQ-002: Another Feature
...
```

After executing 9 phases will run and produce:

```
project_name/
├── include/
│   └── auth.h                      # Core header file
├── src/
│   └── auth.cpp                     # Implementation
├── tests/
│   └── test_auth.cpp               # Test code
├── docs/
│   ├── test_auth_doc.md          # Test documentation (~40+ test cases
│   └── OPENSPEC_EXECUTION_REPORT.md
│   └── code_review_report.md
├── auth_report.md
```

## Code Flow Diagram

```
User Chat (user 
 -> 1. 需求解析
   -> 检测关键词 + 文件读取 (file_reader)
   
 -> 2. 项目创建
    -> 创建目录结构 (include, src, tests, docs
    -> Project structure
   
 -> 3. 代码生成
    -> C++/Python implementation
   
 -> 4. 代码审查 (code_review tool)
   
 -> 5. 自动修复 (auto_fixer tool)
   
 -> 6-9. 测试流程 (TestOrchestrator)
    -> 生成测试文档 (test_doc_generator)
    -> 生成测试代码 (test_generator)
    -> 运行测试 (test_runner)
    -> 更新最终报告
```

## Troubleshooting

### Workflow Not Triggered?

Check:
1. Ensure your request contains a strong trigger keyword
2. Ensure requirements file exists
3. File path is correct
